类型萃取是 C++ 模板元编程的基石。它让编译器在编译期查询类型信息、变换类型、做出选择等

什么是类型萃取

类型萃取是一类编译期元函数：输入一个或多个类型，输出一个编译期常量或另一个类型。

它解决的核心问题是：模板代码在实例化之前，如何根据类型的不同性质，走不同的分支、生成不同的代码？

template <typename T>
void f(T x) {
    if constexpr (std::is_integral_v<T>) {
        // 整数走这里
    } else {
        // 其他类型走这里
    }
}

两大输出

输出 含义 例子
值（bool、size_t 等） 查询类型性质 is_integral_v<T>、alignment_of_v<T>
类型 变换类型 remove_const_t<T>、decay_t<T> 
std::is_integral_v<T>          // 值萃取：得到 bool
std::remove_const_t<T>         // 类型萃取：得到新类型

基石：integral_constant

几乎所有值萃取都建立在 integral_constant 上。它做了三件事：

  • 把值 v 编码进类型。
  • 提供 ::value 访问。
  • 提供 ::type 指向自身，便于统一接口。
template <typename T, T v>
struct integral_constant {
    static constexpr T value = v;
    using value_type = T;
    using type = integral_constant;
    // 类型转换运算符
    constexpr operator T() const noexcept { return v; }
    // 函数调用运算符
    constexpr T operator()() const noexcept { return v; }
};

using true_type  = integral_constant<bool, true>;
using false_type = integral_constant<bool, false>;

std::true_type t;
bool b = t;        // 隐式转换成 bool，b == true
int x = t;         // 隐式转换成 int，x == 1
if (t) { }         // 隐式转换成 bool，条件为真

std::integral_constant<int, 42> c;
int n = c();       // n == 42

true_type 和 false_type 是所有布尔萃取的基类，类型萃取的标准写法：默认继承 false_type，对满足条件的类型偏特化为 true_type

template <typename T>
struct is_integral : std::false_type {};

template <>
struct is_integral<int> : std::true_type {};

C++17 引入 _v 变量模板：

template <typename T>
inline constexpr bool is_integral_v = is_integral<T>::value;

Args> auto invoke(F&& f, Args&&... args) -> std::invoke_result_t<F, Args...> { return std::forward(f)(std::forward(args)...); } ``` 容器优化 `std::vector` 用 `is_trivially_copyable` 决定用 `memcpy` 还是逐个拷贝。 模板约束（C++20 之前） ```cpp template <typename T, typename = std::enable_if_t<std::is_arithmetic_v>> T add(T a, T b) { return a + b; } ``` C++20 之后用 Concept 替代。 --- # C++20 之后还需要类型萃取吗 需要。Concept 替代的是 `enable_if` 和 SFINAE，但： - 值查询仍然用 `is_*_v`。 - 类型变换仍然用 `remove_*_t`、`decay_t` 等。 - Concept 内部仍然用类型萃取定义约束。 例如： ```cpp template concept scalar = std::is_arithmetic_v; ``` Concept 和类型萃取是互补的。 # 类型萃取的常见陷阱 1. **顶层 cv 和引用**：`is_const_v<int&>` 是 `false`，因为引用本身没有 `const`。 2. **数组退化**：`decay_t<int[3]>` 是 `int*`。 3. **函数类型**：`is_class_v` 对函数是 `false`。 4. **`is_convertible` 与 `explicit`**：`explicit` 构造函数不算隐式转换。 5. **不完整类型**：对未定义类型使用某些萃取是未定义行为。 6. **`common_type` 的退化**：`common_type_t<int&, double>` 是 `double`，引用被移除。 # 一句话总结 **类型萃取是编译期的“类型查询”和“类型变换”工具。值萃取回答“T 是不是……”，类型变换回答“把 T 变成……”。它们的实现靠模板偏特化，用途是让模板代码在编译期根据类型性质走不同分支、生成不同代码。C++20 的 Concept 没有取代它们，而是建立在它们之上。**
