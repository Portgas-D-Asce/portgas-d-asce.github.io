类型萃取是 C++ 模板元编程的基石。它让编译器在编译期查询类型信息、变换类型、做出选择等

什么是类型萃取

类型萃取是一类编译期元函数：输入一个或多个类型，输出一个编译期常量或另一个类型。

它解决的核心问题是：模板代码在实例化之前，如何根据类型的不同性质，走不同的分支、生成不同的代码？

template <typename T>
void f(T x) {
    if constexpr (std::is_integral_v<T>) {
        // 整数走这里
    } else {
        // 其他类型走这里
    }
}

两大输出

输出 含义 例子
值（bool、size_t 等） 查询类型性质 is_integral_v<T>、alignment_of_v<T>
类型 变换类型 remove_const_t<T>、decay_t<T> 
std::is_integral_v<T>          // 值萃取：得到 bool
std::remove_const_t<T>         // 类型萃取：得到新类型

基石：integral_constant

几乎所有值萃取都建立在 integral_constant 上。它做了三件事：

  • 把值 v 编码进类型。
  • 提供 ::value 访问。
  • 提供 ::type 指向自身，便于统一接口。
template <typename T, T v>
struct integral_constant {
    static constexpr T value = v;
    using value_type = T;
    using type = integral_constant;
    // 类型转换运算符
    constexpr operator T() const noexcept { return v; }
    // 函数调用运算符
    constexpr T operator()() const noexcept { return v; }
};

using true_type  = integral_constant<bool, true>;
using false_type = integral_constant<bool, false>;

std::true_type t;
bool b = t;        // 隐式转换成 bool，b == true
int x = t;         // 隐式转换成 int，x == 1
if (t) { }         // 隐式转换成 bool，条件为真

std::integral_constant<int, 42> c;
int n = c();       // n == 42

true_type 和 false_type 是所有布尔萃取的基类，类型萃取的标准写法：默认继承 false_type，对满足条件的类型偏特化为 true_type

template <typename T>
struct is_integral : std::false_type {};

template <>
struct is_integral<int> : std::true_type {};

C++17 引入 _v 变量模板：

template <typename T>
inline constexpr bool is_integral_v = is_integral<T>::value;

_v 和 _t 后缀

C++14 起，所有值萃取有 _v 版本：

std::is_integral_v<T>        // 等价于 std::is_integral<T>::value

C++14 起，所有类型变换有 _t 版本：

std::remove_const_t<T>       // 等价于 typename std::remove_const<T>::type

C++17 起，_v 和 _t 成为标准。

典型实现思路

类型萃取的标准实现手法是模板偏特化。

例 1：remove_const

template <typename T>
struct remove_const { using type = T; };

template <typename T>
struct remove_const<const T> { using type = T; };

template <typename T>
using remove_const_t = typename remove_const<T>::type;

例 2：is_pointer

template <typename T>
struct is_pointer : std::false_type {};

template <typename T>
struct is_pointer<T*> : std::true_type {};

例 3：enable_if

template <bool B, typename T = void>
struct enable_if {};

template <typename T>
struct enable_if<true, T> { using type = T; };

template <bool B, typename T = void>
using enable_if_t = typename enable_if<B, T>::type;

只有当 B 为 true 时，enable_if<true, T>::type 才存在，否则 SFINAE 让重载失败。

例 4：void_t

template <typename...>
using void_t = void;

它总为 void，但能触发 SFINAE：

template <typename T, typename = void>
struct has_value_type : std::false_type {};

template <typename T>
struct has_value_type<T, void_t<typename T::value_type>> : std::true_type {};

类型萃取的实际用途

条件分支

template <typename T>
void f(T x) {
    if constexpr (std::is_integral_v<T>) {
        // 整数优化
    } else {
        // 通用路径
    }
}

SFINAE 重载

template <typename T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
void g(T x);

template <typename T, std::enable_if_t<std::is_floating_point_v<T>, int> = 0>
void g(T x);

完美转发与 decay

template <typename F, typename... Args>
auto invoke(F&& f, Args&&... args)
    -> std::invoke_result_t<F, Args...> {
    return std::forward<F>(f)(std::forward<Args>(args)...);
}

容器优化

std::vector 用 is_trivially_copyable 决定用 memcpy 还是逐个拷贝。

模板约束（C++20 之前）

template <typename T,
          typename = std::enable_if_t<std::is_arithmetic_v<T>>>
T add(T a, T b) { return a + b; }

C++20 之后用 Concept 替代。

C++20 之后还需要类型萃取吗

需要。Concept 替代的是 enable_if 和 SFINAE，但：

  • 值查询仍然用 is_*_v。
  • 类型变换仍然用 remove_*_t、decay_t 等。
  • Concept 内部仍然用类型萃取定义约束。

例如：

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

Concept 和类型萃取是互补的。

类型萃取的常见陷阱

  1. 顶层 cv 和引用：is_const_v<int&> 是 false，因为引用本身没有 const。
  2. 数组退化：decay_t<int[3]> 是 int*。
  3. 函数类型：is_class_v 对函数是 false。
  4. is_convertible 与 explicit：explicit 构造函数不算隐式转换。
  5. 不完整类型：对未定义类型使用某些萃取是未定义行为。
  6. common_type 的退化：common_type_t<int&, double> 是 double，引用被移除。

一句话总结

类型萃取是编译期的“类型查询”和“类型变换”工具。值萃取回答“T 是不是……”，类型变换回答“把 T 变成……”。它们的实现靠模板偏特化，用途是让模板代码在编译期根据类型性质走不同分支、生成不同代码。C++20 的 Concept 没有取代它们，而是建立在它们之上。

10 个核心类型萃取逐行拆解

integral_constant：所有值萃取的基石

template <typename T, T v>
struct integral_constant {
    static constexpr T value = v;
    using value_type = T;
    using type = integral_constant;

    constexpr operator T() const noexcept { return v; }
    constexpr T operator()() const noexcept { return v; }
};

using true_type  = integral_constant<bool, true>;
using false_type = integral_constant<bool, false>;

逐行解释：

行 作用
template <typename T, T v> T 是值类型，v 是编码的值
static constexpr T value = v; 把值暴露为编译期常量
using value_type = T; 统一接口，所有萃取都有 value_type
using type = integral_constant; 指向自身，让 ::type 在变换萃取里也统一
operator T() 隐式转换，让对象当值用
operator()() 函数调用，让对象当函数对象用

关键设计：把值编码进类型。true_type 和 false_type 不是值，而是类型。

is_same：最简单的值萃取

template <typename T, typename U>
struct is_same : false_type {};

template <typename T>
struct is_same<T, T> : true_type {};

template <typename T, typename U>
inline constexpr bool is_same_v = is_same<T, U>::value;

逐行解释：

行 作用
主模板继承 false_type 默认两个类型不同
偏特化 <T, T> 继承 true_type 两个类型相同时为真
_v 变量模板 C++17 简写，直接得到 bool

这是模板偏特化最经典的用法：

is_same<int, int>   → 匹配 <T, T> 偏特化 → true_type
is_same<int, double> → 匹配主模板        → false_type

remove_const / remove_cv：最简单的类型变换

template <typename T>
struct remove_const { using type = T; };

template <typename T>
struct remove_const<const T> { using type = T; };

template <typename T>
using remove_const_t = typename remove_const<T>::type;

// remove_cv 类似
template <typename T>
struct remove_cv { using type = T; };

template <typename T>
struct remove_cv<const T> { using type = T; };

template <typename T>
struct remove_cv<volatile T> { using type = T; };

template <typename T>
struct remove_cv<const volatile T> { using type = T; };

逐行解释：

行 作用
主模板 默认返回 T 本身
remove_const<const T> 匹配带 const 的类型，返回 T
remove_cv 三个偏特化 分别处理 const、volatile、const volatile
_t 别名 C++14 简写，直接得到类型

注意：remove_const<const int&> 返回 const int&，因为 const 在引用上不生效。引用本身不能加顶层 const。

remove_const_t<const int>    // int
remove_const_t<const int&>   // const int&（引用上的 const 不生效）
remove_cv_t<const volatile int>  // int

remove_reference：引用处理

template <typename T>
struct remove_reference { using type = T; };

template <typename T>
struct remove_reference<T&> { using type = T; };

template <typename T>
struct remove_reference<T&&> { using type = T; };

template <typename T>
using remove_reference_t = typename remove_reference<T>::type;

逐行解释：

行 作用
主模板 非引用类型，返回自身
<T&> 偏特化 左值引用，返回 T
<T&&> 偏特化 右值引用，返回 T 
remove_reference_t<int&>   // int
remove_reference_t<int&&>  // int
remove_reference_t<int>    // int

is_integral：典型的布尔查询

template <typename T>
struct is_integral : false_type {};

template <> struct is_integral<bool>               : true_type {};
template <> struct is_integral<char>               : true_type {};
template <> struct is_integral<signed char>        : true_type {};
template <> struct is_integral<unsigned char>      : true_type {};
template <> struct is_integral<wchar_t>            : true_type {};
template <> struct is_integral<char16_t>           : true_type {};
template <> struct is_integral<char32_t>           : true_type {};
template <> struct is_integral<short>              : true_type {};
template <> struct is_integral<unsigned short>     : true_type {};
template <> struct is_integral<int>                : true_type {};
template <> struct is_integral<unsigned int>       : true_type {};
template <> struct is_integral<long>               : true_type {};
template <> struct is_integral<unsigned long>      : true_type {};
template <> struct is_integral<long long>          : true_type {};
template <> struct is_integral<unsigned long long> : true_type {};

template <typename T>
inline constexpr bool is_integral_v = is_integral<T>::value;

逐行解释：

行 作用
主模板继承 false_type 默认不是整数
每个整数类型一个全特化 是整数则为真
_v 变量模板 C++17 简写

注意：is_integral<const int> 也是 true。标准库的实现会先移除 cv 再判断：

template <typename T>
struct is_integral : is_integral_impl<remove_cv_t<T>> {};

这样才能正确处理 const int、volatile int 等。

conditional：编译期三目运算符

template <bool B, typename T, typename F>
struct conditional { using type = T; };

template <typename T, typename F>
struct conditional<false, T, F> { using type = F; };

template <bool B, typename T, typename F>
using conditional_t = typename conditional<B, T, F>::type;

逐行解释：

行 作用
主模板 B == true 时返回 T
false 偏特化 B == false 时返回 F
_t 别名 直接得到类型 
conditional_t<true, int, double>   // int
conditional_t<false, int, double>  // double

等价于：

template <bool B, typename T, typename F>
using conditional_t = std::conditional_t<B, T, F>;

这是 std::conditional 的完整实现。关键在于偏特化只对 false 生效，因为主模板已经处理了 true。

enable_if：SFINAE 的核心

template <bool B, typename T = void>
struct enable_if {};

template <typename T>
struct enable_if<true, T> { using type = T; };

template <bool B, typename T = void>
using enable_if_t = typename enable_if<B, T>::type;

逐行解释：

行 作用
主模板 enable_if<B, T> 没有 ::type
true 偏特化 有 ::type = T
_t 别名 直接得到类型

关键：

  • B == true：enable_if_t<true, T> 是 T。
  • B == false：enable_if_t<false, T> 不存在，触发 SFINAE。

用法：

template <typename T, std::enable_if_t<std::is_integral_v<T>, int> = 0>
void f(T x);

template <typename T, std::enable_if_t<std::is_floating_point_v<T>, int> = 0>
void f(T x);

当 T = int 时，第一个重载的 enable_if_t<true, int> 是 int，合法；第二个的 enable_if_t<false, int> 不存在，被移除。所以只有第一个重载参与。

void_t：SFINAE 检测工具

template <typename...>
using void_t = void;

就这一行。但它能做很强大的事：

template <typename T, typename = void>
struct has_value_type : false_type {};

template <typename T>
struct has_value_type<T, void_t<typename T::value_type>> : true_type {};

逐行解释：

行 作用
void_t<Ts...> 无论传入什么，都是 void
has_value_type 主模板 默认 false_type
偏特化 如果 T::value_type 合法，则匹配 void_t<...> = void，为 true_type

关键：void_t 本身总是 void，但它会实例化模板参数。如果 typename T::value_type 不合法，SFINAE 让偏特化失败，回退到主模板。

has_value_type<std::vector<int>>::value  // true
has_value_type<int>::value               // false

decay：综合变换

template <typename T>
struct decay {
private:
    using U = remove_reference_t<T>;
public:
    using type = conditional_t<
        is_array_v<U>,
        conditional_t<
            is_bounded_array_v<U>,
            remove_extent_t<U>*,
            remove_extent_t<U>*
        >,
        conditional_t<
            is_function_v<U>,
            add_pointer_t<U>,
            remove_cv_t<U>
        >
    >;
};

template <typename T>
using decay_t = typename decay<T>::type;

decay 做四件事：

步骤 作用
移除引用 int& → int
移除顶层 cv const int → int
数组转指针 int[3] → int*
函数转函数指针 void(int) → void(*)(int)

例子：

decay_t<int&>              // int
decay_t<const int&>        // int
decay_t<int[3]>            // int*
decay_t<int[3][4]>         // int(*)[4]
decay_t<void(int)>         // void(*)(int)
decay_t<int>               // int

decay 的典型用途是完美转发的返回类型和按值传参的类型推导：

template <typename T>
void f(T&& x) {
    using U = std::decay_t<T>;  // 去掉引用和 cv
    U copy = std::forward<T>(x);
}

common_type：多类型公共类型

// 简化版
template <typename... Ts>
struct common_type;

template <typename T>
struct common_type<T> { using type = decay_t<T>; };

template <typename T, typename U>
struct common_type<T, U> {
    using type = decay_t<decltype(true ? std::declval<T>() : std::declval<U>())>;
};

template <typename T, typename U, typename... Rest>
struct common_type<T, U, Rest...>
    : common_type<typename common_type<T, U>::type, Rest...> {};

逐行解释：

行 作用
单类型特化 返回 decay_t<T>
双类型特化 用三目运算符推导公共类型，再 decay
多类型递归 先算前两个，再和后面的递归

例子：

common_type_t<int, double>         // double
common_type_t<int, long>           // long
common_type_t<int&, const double&> // double
common_type_t<int, double, float>  // double

关键点：

  • 用 decltype(true ? a : b) 让编译器推导类型。
  • 用 decay_t 去掉引用和 cv。
  • 多类型递归展开。

decay 和 remove_cvref 的区别

decay 做四件事

decay_t<T> =
    1. 移除引用
    2. 移除顶层 cv
    3. 数组 → 指针
    4. 函数 → 函数指针

例子：

decay_t<int&>           // int
decay_t<const int&>     // int
decay_t<int[3]>         // int*
decay_t<int[3][4]>      // int(*)[4]
decay_t<void(int)>      // void(*)(int)
decay_t<const int>      // int

remove_cvref 做两件事

template <typename T>
struct remove_cvref {
    using type = remove_cv_t<remove_reference_t<T>>;
};

template <typename T>
using remove_cvref_t = typename remove_cvref<T>::type;

它只做：

1. 移除引用
2. 移除顶层 cv

例子：

remove_cvref_t<int&>           // int
remove_cvref_t<const int&>     // int
remove_cvref_t<int[3]>         // int[3]  ← 不变
remove_cvref_t<int[3][4]>      // int[3][4]  ← 不变
remove_cvref_t<void(int)>      // void(int)  ← 不变
remove_cvref_t<const int>      // int

关键区别

变换 decay remove_cvref
移除引用 ✅ ✅
移除顶层 cv ✅ ✅
数组 → 指针 ✅ ❌
函数 → 函数指针 ✅ ❌ 
decay_t<int[3]>          // int*
remove_cvref_t<int[3]>   // int[3]

decay_t<void(int)>       // void(*)(int)
remove_cvref_t<void(int)> // void(int)

为什么需要 remove_cvref

decay 太激进。有些场景你只想“去掉引用和 cv”，不想把数组变成指针。

比如：

template <typename T>
void f(T&& x) {
    using U = remove_cvref_t<T>;  // 保留数组类型
    // 如果 T 是 int(&)[3]，U 是 int[3]
}

如果用 decay_t，int[3] 会变成 int*，丢失数组大小信息。

另一个场景是返回类型推导：

template <typename T>
auto f(T&& x) -> remove_cvref_t<T> {
    return std::forward<T>(x);
}

这里用 remove_cvref_t 比 decay_t 更精确，因为它不改变数组和函数类型。

标准库里的选择

场景 用哪个
按值传参的类型推导 decay_t
完美转发的返回类型 remove_cvref_t
存储类型（如 std::vector） decay_t
模板元编程中间步骤 remove_cvref_t
C++20 之前 只能用 decay_t 或手动 remove_cv_t<remove_reference_t<T>>
C++20 之后 优先 remove_cvref_t，除非确实需要数组/函数退化

一句话总结

decay = 移除引用 + 移除 cv + 数组转指针 + 函数转函数指针。
remove_cvref = 移除引用 + 移除 cv。
decay 更激进，remove_cvref 更保守。C++20 引入 remove_cvref 就是为了在不需要数组/函数退化时，有一个更精确的工具。
