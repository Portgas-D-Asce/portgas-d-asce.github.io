Concept 是 C++20 引入的模板约束机制。它让模板参数的要求显式、可读、可组合，彻底改变了泛型编程的写法。

什么是 Concept

Concept 是一个编译期的命名谓词：输入一个或多个类型，返回编译期 bool，用于约束模板参数。

一句话： Concept 是给模板参数写的“类型必须满足什么条件”的命名谓词。

它解决的核心问题是： 模板代码在实例化之前，如何显式声明对类型的要求，并在不满足时给出清晰的错误信息？

例如：

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

template <scalar T>
class matrix;

T 是任意类型，scalar 是一个被约束了（必须是算术类型）的类型

没有 Concept 之前的问题

问题 1：错误信息难读

template <typename T>
T add(T a, T b) {
    return a + b;
}

struct Foo {};
add(Foo{}, Foo{});

编译器展开模板后报：

error: no match for 'operator+' (operand types are 'Foo' and 'Foo')
note: in instantiation of function template 'add<Foo>'

用户看到的是 operator+ 缺失，而不是“T 必须支持加法”。

问题 2：SFINAE 复杂难写

template <typename T,
          typename = std::enable_if_t<std::is_arithmetic_v<T>>>
T add(T a, T b) { return a + b; }

问题：

  • 语法复杂。
  • 错误信息仍然难懂。
  • 多个重载容易冲突（enable_if 相同签名）。
  • 约束不能组合。

问题 3：约束不可复用

template <typename T, typename = std::enable_if_t<std::is_arithmetic_v<T>>>
T add(T a, T b);

template <typename T, typename = std::enable_if_t<std::is_arithmetic_v<T>>>
T mul(T a, T b);

同一个约束写了两遍。想改就得改多处。

Concept 的语法

定义

// 名字：concept 的名称
// 条件：编译期布尔表达式，可以是 `is_*_v`、`requires` 表达式、其他 concept 的组合
template <typename T>
concept 名字 = 条件;

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

使用

// 四种写法等价
// 方式 1：作为模板参数约束
template <scalar T>
T add(T a, T b);

// 方式 2：作为 requires 子句
template <typename T>
    requires scalar<T>
T add(T a, T b);

// 方式 3：缩写函数模板
scalar auto add(scalar auto a, scalar auto b);

// 方式 4：作为类型约束
void f(scalar auto x);

检查

scalar<double>       // true
scalar<std::string>  // false

scalar<T> 在编译期返回 bool，可以用于 static_assert、if constexpr、模板参数。

requires 表达式

Concept 的核心是 requires 表达式，它检查一组表达式是否合法。

template <typename T>
concept addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};

拆开看：

部分 含义
requires(T a, T b) 声明“假设存在的变量”
{ a + b } 要求表达式合法
-> std::convertible_to<T> 要求结果可转 T

requires 表达式有四种要求。

  • 简单要求
  • 类型要求
  • 复合要求
  • 嵌套要求
// 简单要求
template <typename T>
concept has_foo = requires(T a) {
    a.foo();       // a.foo() 必须合法
    a.bar(1);      // a.bar(1) 必须合法
};

// 类型要求
template <typename T>
concept has_value_type = requires {
    typename T::value_type;   // T 必须有嵌套类型 value_type
};

// 复合要求
template <typename T>
concept addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;  // a+b 合法，结果可转 T
    { a * b } noexcept;                    // a*b 合法，不抛异常
};

// 嵌套要求
template <typename T>
concept small = requires(T a) {
    requires sizeof(T) <= 8;   // 额外条件
    requires std::is_trivial_v<T>;
};

复合要求的三种形式：

形式 含义
{ expr }; expr 合法
{ expr } -> Concept; expr 合法，且结果满足 Concept
{ expr } noexcept; expr 合法，且不抛异常

requires 表达式的求值规则

  • 所有要求都满足 → true。
  • 任意一个要求不满足 → false。
  • 不满足时不会报错，只是返回 false。

关键：requires 表达式不执行任何代码，只检查表达式是否合法。

Concept 的分类

Concept 可按来源分三类。

标准库 Concept

C++20 在 <concepts> 和 <iterator> 等头文件里提供了大量标准 Concept。

核心语言相关：

Concept 含义
std::same_as<T, U> T 和 U 是同一类型
std::derived_from<D, B> D 继承自 B
std::convertible_to<From, To> From 可隐式转 To
std::common_reference_with<T, U> 有公共引用类型
std::common_with<T, U> 有公共类型
std::integral<T> T 是整数
std::signed_integral<T> T 是有符号整数
std::unsigned_integral<T> T 是无符号整数
std::floating_point<T> T 是浮点
std::assignable_from<L, R> R 可赋给 L
std::swappable<T> T 可交换
std::destructible<T> T 可析构
std::constructible_from<T, Args...> T 可用 Args... 构造
std::default_initializable<T> T 可默认构造
std::move_constructible<T> T 可移动构造
std::copy_constructible<T> T 可拷贝构造

比较相关：

Concept 含义
std::equality_comparable<T> T 支持 ==
std::totally_ordered<T> T 支持全序比较
std::three_way_comparable<T> T 支持 <=>

对象相关：

Concept 含义
std::movable<T> 可移动、可交换
std::copyable<T> 可拷贝、可移动
std::semiregular<T> 可拷贝、可默认构造
std::regular<T> 半正则 + 相等比较
std::invocable<F, Args...> F 可用 Args... 调用
std::predicate<F, Args...> F 是谓词
std::relation<R, T, U> R 定义 T 和 U 的关系
std::equivalence_relation<R, T, U> 等价关系
std::strict_weak_order<R, T, U> 严格弱序

范围相关（<ranges>）：

Concept 含义
std::range<R> R 是范围
std::sized_range<R> 有 size()
std::view<R> R 是视图
std::input_range<R> 输入范围
std::forward_range<R> 前向范围
std::random_access_range<R> 随机访问范围
std::contiguous_range<R> 连续范围

自定义 Concept

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

template <typename M>
concept matrix_like = requires(M m, index_t i, index_t j) {
    { m.rows() } -> std::convertible_to<index_t>;
    { m.cols() } -> std::convertible_to<index_t>;
    { m(i, j) };
    typename M::value_type;
};

组合 Concept

template <typename T>
concept numeric = scalar<T> && std::totally_ordered<T>;

template <typename T>
concept small_numeric = numeric<T> && (sizeof(T) <= 8);

Concept 的组合

Concept 可以用逻辑运算符组合。

合取 &&

template <typename T>
concept small_scalar = scalar<T> && (sizeof(T) <= 8);

small_scalar<T> 为真当且仅当两个条件都满足。

析取 ||

template <typename T>
concept numeric = std::integral<T> || std::floating_point<T>;

numeric<T> 为真当且仅当至少一个条件满足。

否定 !

template <typename T>
concept non_scalar = !scalar<T>;

组合的短路求值

template <typename T>
concept has_foo_and_bar = requires(T a) { a.foo(); }
                       && requires(T a) { a.bar(); };

如果第一个 requires 为 false，第二个不再求值。这叫约束的短路。

约束的偏序

多个约束可以按“严格程度”排序：编译器会选择约束更强的重载

template <typename T> concept A = ...;
template <typename T> concept B = A<T> && ...;

template <A T> void f(T);  // 约束较弱
template <B T> void f(T);  // 约束较强，优先匹配

Concept 与模板实例化

约束检查时机

template <scalar T>
T add(T a, T b) { return a + b; }

add(1, 2);        // OK，T = int
add(1.0, 2.0);    // OK，T = double
add("a", "b");    // 编译错误：const char* 不满足 scalar

错误信息比 SFINAE 的错误信息清楚得多

error: constraint 'scalar<const char*>' not satisfied

约束与重载决议

约束参与重载决议。如果两个重载都满足，选约束更强的

template <typename T> requires std::integral<T>
void f(T) { std::cout << "integral\n"; }

template <typename T> requires std::floating_point<T>
void f(T) { std::cout << "floating\n"; }

f(1);     // integral
f(1.0);   // floating
f("a");   // 编译错误：没有匹配的重载

约束与偏特化

Concept 可以用于类模板偏特化

template <typename T>
struct wrapper { };

template <std::integral T>
struct wrapper<T> { };  // 仅对整数特化

Concept 与类型萃取的关系

Concept 不是替代类型萃取，而是建立在类型萃取和 requires 表达式之上的更高层抽象。

层次 工具 用途
底层 is_arithmetic_v、is_same_v 查询类型性质
中层 requires 表达式 检查表达式合法性
上层 Concept 命名谓词，约束模板参数
应用 template <scalar T> 泛型算法 
// Concept 内部用类型萃取

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

// Concept 内部用 `requires`
template <typename T>
concept addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};

// Concept 替代 `enable_if`
// C++17
template <typename T, typename = std::enable_if_t<std::is_arithmetic_v<T>>>
T add(T a, T b);

// C++20
template <scalar T>
T add(T a, T b);

// Concept 不能替代类型变换, 只做约束，不做变换
std::remove_const_t<T>   // 仍然是类型萃取
std::decay_t<T>          // 仍然是类型萃取

Concept 的实际用途

约束模板参数

template <scalar T, index_t Rows = dynamic, index_t Cols = dynamic>
class matrix;

约束泛型算法

template <vector_like V>
auto norm2(const V& v);

替代 SFINAE 重载

template <std::integral T>
void f(T x);

template <std::floating_point T>
void f(T x);

约束类模板偏特化

template <typename T>
struct container;

template <std::integral T>
struct container<T> { /* 整数版本 */ };

template <std::floating_point T>
struct container<T> { /* 浮点版本 */ };

缩写函数模板: scalar auto 是 template <scalar T> void print(T x) 的简写。

void print(scalar auto x) {
    std::cout << x << "\n";
}

约束返回值

template <typename T>
concept has_begin = requires(T t) { t.begin(); };

template <has_begin T>
auto first(const T& t) {
    return *t.begin();
}

编译期分支: 这里用的是标准库 Concept，不是 is_*_v

template <typename T>
void f(T x) {
    if constexpr (std::integral<T>) {
        // 整数路径
    } else if constexpr (std::floating_point<T>) {
        // 浮点路径
    }
}

Concept 的常见陷阱

requires 表达式不执行代码

template <typename T>
concept bad = requires(T a) {
    a.foo();   // 只检查 a.foo() 是否合法，不实际调用
};

requires 表达式内的变量是假想的

template <typename T>
concept addable = requires(T a, T b) {
    a + b;   // a 和 b 是假想对象，不真实存在
};

Concept 不能有默认参数

template <typename T = int>   // 错误：Concept 不能有默认模板参数
concept scalar = std::is_arithmetic_v<T>;

Concept 不能被显式实例化

scalar<double>;   // 这是检查，不是实例化

Concept 的短路可能隐藏错误: 如果 t.size() 不合法，第二个 requires 不求值，has_size 为 false，不会报错

template <typename T>
concept has_size = requires(T t) { t.size(); }
                 && requires(T t) { t.size() > 0; };

Concept 不能约束非类型模板参数

template <int N>
concept positive = (N > 0);   // 错误：Concept 只约束类型

非类型模板参数用 requires 子句：

template <int N> requires (N > 0)
void f();

requires 子句和 requires 表达式不同: 一个是约束语法，一个是表达式语法。名字相同，含义不同。

// requires 子句
template <typename T> requires scalar<T>
void f();

// requires 表达式
template <typename T>
concept addable = requires(T a, T b) { a + b; };

Concept 的求值顺序: 先检查 A<T>，再检查 B。如果 A<T> 为 false，B 的第二个 requires 不求值。

template <typename T>
concept A = requires(T t) { t.foo(); };
template <typename T>
concept B = A<T> && requires(T t) { t.bar(); };

Concept vs 类型萃取 vs SFINAE

维度 类型萃取 SFINAE Concept
引入版本 C++11 C++11 C++20
作用 查询/变换类型 条件启用重载 命名约束
语法 is_*_v、remove_*_t enable_if、void_t concept、requires
错误信息 中等 差 好
可组合 有限 差 好
可读性 中 差 好
重载冲突 容易 容易 按约束偏序
是否替代 — 被 Concept 替代 —

关系：

类型萃取 → 提供底层布尔和类型变换
SFINAE   → 用类型萃取做条件启用

Concept 替代的是 SFINAE，不是类型萃取。

一句话总结

Concept 是 C++20 的命名约束：用 requires 表达式或类型萃取定义，返回编译期 bool，用于约束模板参数。它替代了 enable_if 和 SFINAE，让模板代码更可读、错误信息更友好、约束可组合。但它不替代类型萃取——类型萃取仍然用于查询和变换类型，Concept 建立在它们之上。

附: 命名谓词

什么是谓词

谓词（predicate） 就是“返回 bool 的东西”。

数学里： $P(x)$ 是一个谓词，表示“ $x$ 满足某性质”，结果是真或假。

C++ 里：is_even 就是一个谓词。给它一个 x，它返回 true 或 false。

bool is_even(int x) {
    return x % 2 == 0;
}

所以谓词的本质是： 输入一个东西，输出一个布尔值。

什么是“命名”

如果不给谓词起名字，你只能在需要的地方临时写条件：

template <typename T>
    requires (std::is_arithmetic_v<T>)
class matrix;

这个 std::is_arithmetic_v<T> 就是一个匿名谓词——它能判断，但没有名字。

给它起个名字：

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

scalar 就是命名谓词。

之后可以写：

template <scalar T>
class matrix;

而不是每次重复 std::is_arithmetic_v<T>。

所以“命名”的意思是： 把一组类型要求打包，起一个名字，之后用名字代替那组要求。

Concept 就是命名谓词

Concept 的语法：

template <typename T>
concept 名字 = 条件;
  • 左边 名字：给谓词起的名字。
  • 右边 条件：一个编译期布尔表达式。
  • T：谓词的参数，代表“被检查的类型”。

所以：

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

读作： 定义一个名为 scalar 的谓词，输入类型 T，当 T 是算术类型时返回 true。

普通谓词 vs Concept

  普通谓词 Concept
输入 值 类型
返回 bool 编译期 bool
求值时机 运行时 编译期
用途 条件判断 约束模板参数
例子 is_even(4) scalar<double>

普通谓词：

bool is_even(int x);       // 输入值，运行时返回 bool
is_even(4);                 // true

Concept：

template <typename T>
concept scalar = ...;       // 输入类型，编译期返回 bool
scalar<double>              // true

scalar<double> 看起来像函数调用，其实是编译期布尔值。

为什么叫“谓词”而不是“函数”

因为 Concept 不是函数。它：

  • 不在运行时执行，只在编译期求值。
  • 不能取地址，不能当函数指针。
  • 参数是类型，不是值。
  • 结果只用于约束，不产生运行时行为。

它更像数学里的谓词： $P(T)$：类型 $T$ 满足某性质, 而不是 C++ 函数。

六、Concept 可以组合

命名谓词的好处之一是可组合：

template <typename T>
concept scalar = std::is_arithmetic_v<T>;

template <typename T>
concept ordered = requires(T a, T b) { { a < b } -> std::convertible_to<bool>; };

template <typename T>
concept numeric = scalar<T> && ordered<T>;

numeric 也是一个命名谓词，由两个命名谓词组合而成。

用起来：

template <numeric T>
T clamp(T x, T lo, T hi);

读作：T 必须满足 numeric：既是标量，又可比较。

七、和“命名谓词”对应的还有“匿名谓词”

// 匿名谓词：直接写条件
template <typename T>
    requires (std::is_arithmetic_v<T> && (sizeof(T) <= 8))
class matrix;

// 命名谓词：起名字
template <typename T>
concept small_scalar = std::is_arithmetic_v<T> && (sizeof(T) <= 8);

template <small_scalar T>
class matrix;

命名谓词的好处：

  • 可读：small_scalar<T> 比 std::is_arithmetic_v<T> && sizeof(T) <= 8 清楚。
  • 可复用：多个模板可以共用同一个 concept。
  • 可组合：concept A = B<T> && C<T>;
  • 错误信息友好：编译器直接说 small_scalar<T> 不满足，而不是展开一长串表达式。
