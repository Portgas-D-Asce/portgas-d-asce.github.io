decltype

是什么

decltype(expr) 是一个说明符：输入一个表达式，返回它的类型，不求值。

int x = 0;
decltype(x) y = 1;        // y 是 int
decltype(1 + 2.0) z = 0;  // z 是 double

三条规则

e 的形式 decltype(e)
未加括号的标识符或类成员访问 该标识符声明时的类型
左值表达式 T&
纯右值表达式 T
将亡值表达式 T&& 
int x = 0;
const int cx = 0;
int& r = x;

decltype(x)     // int
decltype(cx)    // const int
decltype((x))   // int&，加括号变成左值表达式
decltype(r)     // int&
decltype(x + 0) // int，纯右值

与 auto 的区别

  auto decltype
推导依据 初始化表达式，按值推导 表达式的类型，精确推导
引用 去掉引用 保留引用
const 去掉顶层 const 保留 const
数组 退化为指针 保留数组类型
用途 变量声明 返回类型、SFINAE、元编程 
int x = 0;
int& r = x;
const int cx = 0;

auto a = r;          // int
decltype(r) b = x;   // int&

auto c = cx;         // int
decltype(cx) d = 0;  // const int

decltype(auto)（C++14）

按 decltype 规则推导返回类型，保留引用和 const。

decltype(auto) f() { return x; }   // 返回 int&，因为 x 是左值
auto f() { return x; }             // 返回 int，按值

典型用途

1. 返回类型推导（C++11 尾置返回类型）

template <typename A, typename B>
auto add(A a, B b) -> decltype(a + b) {
    return a + b;
}

2. SFINAE： t.foo() 不合法 → decltype 替换失败 → SFINAE。

template <typename T>
auto f(T t) -> decltype(t.foo()) {
    return t.foo();
}

3. 类型萃取

template <typename A, typename B>
using add_result_t = decltype(
    std::declval<A>() + std::declval<B>()
);

实现原理

decltype 是编译器关键字，不是标准库组件。以 Clang 和 GCC 为例：

整体流程：

源码: decltype(expr)
    ↓
[Parser] 解析为 DecltypeType 节点 / DECLTYPE_TYPE 树节点
    ↓
[Sema] 对 expr 进行类型推导，得到 UnderlyingType
    ↓
[AST] 生成 DecltypeType(E, UnderlyingType)
    ↓
[CodeGen] 直接使用 UnderlyingType，不做额外计算

Clang：

  • AST 节点：DecltypeType，保存 Expr *E 和 QualType UnderlyingType。
  • Sema 阶段先分析表达式的值类别和类型，再按规则决定 UnderlyingType。
  • DecltypeType 不被唯一化（每个 decltype 有自己的 AST 节点）。
  • Lambda 中 decltype((x)) 有上下文敏感的特殊处理。
  • CodeGen 直接使用 UnderlyingType，decltype 不产生运行时行为。

GCC：

  • 树节点：DECLTYPE_TYPE，定义在 cp-tree.def。
  • 宏 DECLTYPE_TYPE_EXPR 取出内部表达式。
  • 宏 DECLTYPE_TYPE_ID_EXPR_OR_MEMBER_ACCESS_P 标记是否为“未加括号的标识符或成员访问”。
  • 模板中始终视为依赖类型，实例化时由 tsubst 重新计算。

关键设计要点：

要点 说明
不求值 操作数在 Unevaluated 上下文中分析
保留引用和 cv 与 auto 不同，不退化类型
括号规则 decltype(x) 与 decltype((x)) 不同
依赖类型 模板中始终 dependent，实例化时才确定
不唯一化 每个 decltype 表达式有独立 AST 节点

常见陷阱

int x = 0;
decltype(x)   // int
decltype((x)) // int&，加括号改变结果

int& f();
decltype(f())  // int&
auto x = f();  // int

decltype(x++)  // int，x++ 不求值
decltype(++x)  // int&，++x 不求值

declval

是什么

std::declval<T>() 是函数模板，返回 T&&，但不构造对象。用于编译期类型推导。

一句话： 在编译期“假装”有一个 T 类型的对象，只用于 decltype、sizeof、noexcept 等不求值上下文。

实现原理

标准定义（<utility>）：只有声明，没有定义。

template <class T>
add_rvalue_reference_t<T> declval() noexcept;

libstdc++ 实际源码：

template<typename _Tp>
  _GLIBCXX_CONSTEXPR typename std::add_rvalue_reference<_Tp>::type
  declval() noexcept;

libc++ 实际源码：

template <class _Tp>
_LIBCPP_HIDE_FROM_ABI typename add_rvalue_reference<_Tp>::type declval() _NOEXCEPT;

为什么没有函数体

declval 只用于不求值上下文：这些上下文里函数不会被实际调用，编译器只需返回类型。

  • decltype(declval<T>().foo())
  • sizeof(declval<T>())
  • noexcept(declval<T>().foo())

如果用户真调用：这是故意设计：防止运行期调用，只在链接期报错。

auto x = std::declval<int>();   // 链接错误：未定义的引用

为什么用 add_rvalue_reference_t<T> 而不是 T&&

因为 T&& 对某些类型不合法：

T T&& add_rvalue_reference_t<T>
int int&& int&&
int& int& && → int& int&
int&& int&& && → int&& int&&
void void&& 不合法 void

add_rvalue_reference 的源码：用 __void_t<_Tp&&> 做 SFINAE 检测 T&& 是否合法。

template<typename _Tp, typename = void>
struct __add_rvalue_reference_helper {
    typedef _Tp type;   // 回退：T&& 不合法时返回 T（处理 void）
};

template<typename _Tp>
struct __add_rvalue_reference_helper<_Tp, __void_t<_Tp&&>> {
    typedef _Tp&& type;   // T&& 合法时返回 T&&
};

template<typename _Tp>
struct add_rvalue_reference
    : public __add_rvalue_reference_helper<_Tp> {};

为什么 noexcept

declval 没有函数体，逻辑上不可能抛异常。标 noexcept 让它在 noexcept 表达式里可用：

template <typename T>
constexpr bool is_nothrow_foo() {
    return noexcept(std::declval<T>().foo());
}

decltype 与 declval 的配合

为什么需要配合

在 decltype 里需要一个 T 类型的对象，declval 解决了这个问题：

  • 不能写 T{}.foo()：T 可能没有默认构造函数。
  • 不能写 T().foo()：同上。
  • 不能写 T t; t.foo()：decltype 里不能声明变量。
decltype(std::declval<T>().foo())

配合流程

declval<T>()  →  返回 T&&，假装有 T 对象
    ↓
.foo()        →  调用成员函数
    ↓
decltype(...) →  推导返回类型
    ↓
不合法        →  SFINAE

典型用例

检测成员函数

template <typename T, typename = void>
struct has_foo : std::false_type {};

template <typename T>
struct has_foo<T, std::void_t<decltype(std::declval<T>().foo())>>
    : std::true_type {};

检测运算符

template <typename T, typename = void>
struct has_plus : std::false_type {};

template <typename T>
struct has_plus<T, std::void_t<decltype(
    std::declval<T>() + std::declval<T>()
)>> : std::true_type {};

推导表达式类型

template <typename A, typename B>
using add_result_t = decltype(
    std::declval<A>() + std::declval<B>()
);

检测可转换性

template <typename From, typename To, typename = void>
struct is_convertible : std::false_type {};

template <typename From, typename To>
struct is_convertible<From, To, std::void_t<decltype(
    static_cast<To>(std::declval<From>())
)>> : std::true_type {};

检测迭代器

template <typename T, typename = void>
struct is_iterable : std::false_type {};

template <typename T>
struct is_iterable<T, std::void_t<
    decltype(std::begin(std::declval<T>())),
    decltype(std::end(std::declval<T>()))
>> : std::true_type {};

libstdc++ 中的 declval 实现细节

标准库自身也用 decltype + 重载决议实现 declval：

template<typename _Tp, typename _Up = _Tp&&>
_Up __declval(int);

template<typename _Tp>
_Tp __declval(long);

template<typename _Tp>
auto declval() noexcept -> decltype(__declval<_Tp>(0));
  • 第一个重载返回 _Up = _Tp&&。
  • 第二个重载返回 _Tp。
  • __declval<_Tp>(0) 优先匹配第一个（int 比 long 更匹配）。
  • 如果 _Tp&& 不合法，第一个重载 SFINAE 失败，回退到第二个。
  • 用 decltype 推导最终返回类型。

总结

decltype 是编译器关键字，在 Sema 阶段按值类别推导表达式类型，存入 AST 节点，CodeGen 直接使用结果，不产生运行时逻辑。

declval 是一个只有声明的函数模板，返回 add_rvalue_reference_t<T>，在编译期假装有 T 对象，只用于不求值上下文。两者配合是 SFINAE 检测成员、运算符、返回类型的核心工具。
