奇异递归模板模式（Curiously Recurring Template Pattern，CRTP）

CRTP（Curiously Recurring Template Pattern，奇异递归模板模式） 是 C++ 模板编程中的一种经典技巧：一个派生类将自己作为模板参数传递给基类，使得基类能够在编译期知道派生类的类型，从而在基类的方法中调用派生类的成员函数——实现编译期多态（静态多态）。

1. 基本形式

template <typename Derived>
class Base {
public:
    void interface() {
        // 编译期将 this 转换为 Derived*，然后调用派生类的实现
        static_cast<Derived*>(this)->implementation();
    }

    // 可选：提供默认实现，若派生类没有则使用默认
    void implementation() {
        // 默认行为
    }
};

class MyClass final : public Base<MyClass> {
    friend class Base<MyClass>;
private:
    void implementation() {
        // 派生类定制行为
    }
};

// 使用
MyClass obj;
obj.interface();  // 调用 Base::interface，内部调用 MyClass::implementation

关键：

  • 基类 Base 接受模板参数 Derived。
  • 派生类 MyClass 继承自 Base<MyClass>（自己作为模板参数传给基类）。
  • 基类通过 static_cast<Derived*>(this) 安全地向下转型，因为 this 实际指向的就是 Derived 对象，这是类型安全的（没有任何虚函数或运行时开销）。

原理：编译期多态（静态多态）

CRTP 是静态多态的典型实现方式，与虚函数的动态多态对比：

特性 CRTP（静态多态） 虚函数（动态多态）
绑定时机 编译期 运行时（通过 vtable）
调用开销 直接函数调用，可内联 间接调用（查虚表），难以内联
对象大小 无虚指针，更小 包含 vptr，增大对象
灵活性 必须在编译时确定派生类类型 可动态绑定到任意派生类
代码膨胀 每个派生类实例化一份基类代码 只一份基类代码

核心机制：static_cast<Derived*>(this) 是安全的，因为派生类 MyClass 继承自 Base<MyClass>，所以 this 的运行时类型一定是 MyClass*。编译器可以完全优化掉转型，直接调用派生类的函数，甚至可以内联。

典型应用场景

场景 A：静态多态（编译期多态）

替代虚函数接口，用于对性能要求极高的场景（如游戏引擎、高频交易），且派生类数量在编译期已知。

template <typename Derived>
class Algorithm {
public:
    void run() {
        static_cast<Derived*>(this)->step1();
        static_cast<Derived*>(this)->step2();
    }
};

class FastAlgo : public Algorithm<FastAlgo> {
public:
    void step1() { /* 快速实现 */ }
    void step2() { /* 快速实现 */ }
};

通过 CRTP，基类可以定义算法骨架，派生类实现具体步骤，没有虚函数开销。

场景 B：对象计数器（实例计数）

跟踪某个类创建了多少个对象，而且每个派生类拥有独立的计数器（利用模板实例化）。

template <typename Derived>
class Counted {
public:
    Counted() { ++count; }
    ~Counted() { --count; }
    static int objectsAlive() { return count; }
private:
    static int count;
};

template <typename Derived>
int Counted<Derived>::count = 0;

class MyWidget : public Counted<MyWidget> {};
class MyGadget : public Counted<MyGadget> {};

// MyWidget 和 MyGadget 各自维护独立的计数

场景 C：实现 enable_shared_from_this 的类似机制

CRTP 可以让基类方法返回指向派生类的指针/引用，且类型是派生类而非基类，从而支持链式调用。

template <typename Derived>
class Base {
public:
    Derived& setProperty(int value) {
        // ... 设置公共属性
        return static_cast<Derived&>(*this);   // 返回派生类引用
    }
};

class Widget : public Base<Widget> {
public:
    Widget& setColor(const std::string& c) {
        // ...
        return *this;
    }
};

Widget w;
w.setProperty(5).setColor("red");   // 流畅接口

场景 D：操作符重载辅助（如 Boost.Operators）

通过 CRTP 自动为派生类生成运算操作符，只需派生类提供少量基本操作。

例如，只需提供 operator< 和 operator==，CRTP 基类自动生成 operator>、<=、>=、!=。

场景 E：混入类（Mixins）

混入类通过 CRTP 为类添加额外功能，而不影响类的主要职责。

template <typename Derived>
class Singleton {
public:
    static Derived& getInstance() {
        static Derived instance;
        return instance;
    }
protected:
    Singleton() = default;
};

class MyManager : public Singleton<MyManager> {
    friend class Singleton<MyManager>;
    // 私有构造等
};

CRTP 的高级技巧：多层继承与委托

CRTP 可以嵌套多层，基类又可以 CRTP 到另一个基类，形成链式调用。也可以在基类中检测派生类是否提供了某个方法（通过 SFINAE 或 concepts），如果未提供则使用基类的默认实现——这被称为 静态多态的“默认方法”。

5. CRTP 的优缺点

优点：

  • 零运行时开销：无虚表，调用可内联，性能极致。
  • 对象体积更小：没有虚指针。
  • 类型安全：编译期检查，转型安全。
  • 灵活组合：通过混入可以按需组合类功能。

缺点：

  • 代码膨胀：每个派生类都会实例化一份基类代码，多个派生类可能导致二进制体积增大。
  • 不能动态切换：无法在运行时通过基类指针/引用统一处理不同的派生类对象（失去动态多态性）。
  • 模板深度依赖：错误信息长且难以阅读（C++20 concepts 有所改善）。
  • 无法存储异构容器：不能像 vector<Base*> 那样存储不同派生类对象。

现代 C++（C++20）对 CRTP 的增强

C++20 引入了 concepts，使得 CRTP 中的类型约束更加清晰，错误信息更友好。可以约束派生类必须实现哪些方法，否则在模板实例化早期就报错。

template <typename Derived>
concept DerivedImpl = requires(Derived d) {
    { d.implementation() } -> std::same_as<void>;
};

template <DerivedImpl Derived>
class Base {
public:
    void interface() {
        static_cast<Derived*>(this)->implementation();
    }
};

这样，如果派生类未实现 implementation()，会在编译时给出简洁的错误：“约束不满足”。

why

完全可以直接创建派生类么，定义接口函数和实现函数么，为什么非要用 crtp

不用 crtp

class A {
public:
    void run() {
        // 相同的前置处理
        doA();     // 不同
        // 相同的后置处理
    }
};
class B {
public:
    void run() {
        // 相同的前置处理   ← 重复
        doB();             // 不同
        // 相同的后置处理   ← 重复
    }
};

用 crtp

template <typename Derived>
class Base {
public:
    void run() {
        // 相同的前置处理（只写一次）
        static_cast<Derived*>(this)->doWork();
        // 相同的后置处理（只写一次）
    }
};

class A : public Base<A> {
public:
    void doWork() { /* A 的特化 */ }
};
class B : public Base<B> {
public:
    void doWork() { /* B 的特化 */ }
};

总结

CRTP 是通过把派生类类型注入基类，实现编译期向下转型，从而在基类中调用派生类方法的技术。
它适合在以下场景中使用：

  • 需要虚函数的性能敏感代码。
  • 想为多个类添加通用功能（计数、操作符重载、单例等）而不损失性能。
  • 实现静态接口（如模板方法模式）且派生类类型编译期确定。

但它不是虚函数的完全替代品——不能动态派发，不能在容器中存储异构对象。
在你进一步学习模板元编程或设计高性能库时，CRTP 会是一个频繁出现的武器。
